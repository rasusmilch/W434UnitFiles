Keywords

Keywords are words that have a specific meaning in ATS. They cannot be re-defined or be used as identifiers. Keywords in ATS are: adds_to_net_list, affects, AND, begin, case, constants, default, do, else, end, for, function, if, main, manualtest, NOT, OR, rangetest, removes_from_net_list, switch, template, tests, to, var, while

Comments

Comments are used to add explanatory words to the program code in a natural language. They can also be used to deactivate program lines. Comments are ignored by the compiler.
They can be identified in different ways:


{ Text between an open and a close brace. }

// Any text between a double forward slash and the end of a line.

Variables

A variable is a memory location in an ATS program that can assume different values. This memory location is addressed with the name of the variable.
In ATS, variable names must begin with an upper case letter (A..Z). This can be followed by upper case letters (A..Z), lower case letters (a..z), digits (0..9) and the underscore character (_).
Each variable in ATS must be initialised by an assignment before it is used for the first time.

Data types

By assigning a data type to a variable, it is possible to define the values which the variable can assume. In ATS, data types need only be assigned to variables in the parameters of functions. Otherwise ATS provides dynamic data type adaptation.
Data types in CEETIS are:
Data type Description
string Strings are strings of characters. This data type expects texts that are delimited by single speech marks. Example: ’Text’
integer An integer is a whole-number value with an optional sign in front of it. Variables of the integer type can assume values between -2147483648 and 2147483647.
boolean Variables of the boolean type can only assume two values: TRUE and FALSE. They are used for logical expressions. FALSE is defined internally with "0" and TRUE with "not equal 0". Consequently, constants such as ON (1) and OFF (0) can also be used for the function parameters of the boolean data type.
real Real values are floating-point numbers within the range 5.0E-324 to 1.7E308 with both a plus and minus sign. The full-stop is always used as the decimal separator in ATS. Thousand separators are not permitted.
tnetlistrow tnetlistrow is the data type for the rows of the netlist. Variables of the tnetlistrow type can assume whole-number values between 1 and 2147483647. There are also the constants NETLIST_FirstRow and NETLIST_LastRow available.
void The data type void is only used for functions. If a function is of the void type, it cannot and may not return a function value.
tcurrent tcurrent is the data type for expressing electrical current. In ATS, current is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for electrical current is the ampere (A). Examples: 0.1A, 10mA
tvoltage tvoltage is the data type for expressing voltage. In ATS, voltage is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for electrical voltage is the volt (V). Examples: 100mV, 12V, 1kV
tresistance tresistance is the data type for expressing electrical resistance. In ATS, resistance is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for electrical resistance is the ohm (Ohm). Examples: 100mOhm, 470Ohm, 1MOhm
tcapacitance tcapacitance is the data type for expressing capacitance. In ATS, capacitance is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for electrical capacitance is the farad (F). Examples: 100nF, 10uF, 1mF
tpower tpower is the data type for expressing power. In ATS, power is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for electrical power is the watt (W). Examples: 1mW, 0.1W, 10W
tinductance tinductance is the data type for expressing inductance. In ATS, inductance is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for inductance is the henry (H). Examples: 100uH, 10mH, 1H
tfrequency tfrequency is the data type for expressing frequency. In ATS, frequency is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for frequency is the hertz (Hz). Examples: 50Hz, 1kHz, 1MHz
ttime ttime is the data type for expressing time. In ATS, time is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for time is the second (s). Examples: 10ms, 1s
tlength tlength is the data type for expressing length. In ATS, length is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for length is the meter (m). Examples: 10mm, 1m
tvoltageramp tvoltageramp is the data type for expressing voltage ramps. In ATS, voltage ramps are expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The basic unit for a voltage ramp is volt per second (Vps). Examples: 500Vps, 2kVpms
tattenuation tattenuation is the data type for expressing attenuation. In ATS, attenuation is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The unit for attenuation is the decibel (dB). Example: 10dB
tpowerlevel tpowerlevel is the data type for expressing a powerlevel. In ATS, a powerlevel is expressed as a combination of a floating-point value and a unit. There must be no blanks between the value and the unit. The unit for powerlevels is the decibel milliwatt (dBm). Example: -10dBm
tpin tpin is the data type for test pins. Pins are indicated by their name in double speech marks. Examples: "Pin1", "1"
tpowerupin tpowerupin is the data type for power U-pins. Power U-pins are indicated by their name in double speech marks. Examples: "PowerUPin1", "1"
tpoweripin tpoweripin is the data type for power I-pins. Power I-pins are indicated by their name in double speech marks. Examples: "PowerIPin1", "1"
tpowermpin tpowermpin is the data type for power M-pins. Power M-pins are indicated by their name in double speech marks. Examples: "PowerMPin1", "1"
tled tled is the data type for LEDs. LEDs are indicated by their name in double speech marks. Examples: "LED1", "1"
tcontact tcontact is the data type for contacts. Contacts are indicated by their name in double speech marks. Examples: "Contact1", "1"
topticalpin topticalpin is the data type for pins of the optical matrix. Contacts are indicated by their name in double speech marks. Examples: "OpticalPin1", "1"
tpowerupinabs tpowerupinabs is the data type for the absolute addressing of power U-pins. Absolute addresses of power U-pins are the connector number and pin, separated by a full-stop and enclosed in double speech marks. Examples: "1.a1", "1.2"
tpoweripinabs tpoweripinabs is the data type for the absolute addressing of power I-pins. Absolute addresses of power I-pins are the connector number and pin, separated by a full-stop and enclosed in double speech marks. Examples: "2.a1", "2.2"
tpowermpinabs tpowermpinabs is the data type for the absolute addressing of power M-pins. Absolute addresses of power M-pins are the connector number and pin, separated by a full-stop and enclosed in double speech marks. Examples: "3.a1", "3.2"
tledabs tledabs is the data type for the absolute addressing of LEDs. Absolute addresses of LEDs are the connector number and pin, separated by a full-stop and enclosed in double speech marks. Examples: "4.a1", "4.2"
tcontactabs tcontactabs is the data type for the absolute addressing of contacts. Absolute addresses of contacts are the connector number and pin, separated by a full-stop and enclosed in double speech marks. Examples: "5.a1", "5.2"
tlvpin tlvpin is the data type for pins of the W484-PLUS-Matrix. You must pass pins which are tagged as "Test" in the pin table at places where the type tlvled is required. PLUS pins are indicated by their name in double speech marks. Examples: "PLUS Pin1", "1"
tlvled tlvled is the data type for LEDs of the W484-PLUS-Matrix. You must pass pins which are tagged as "LED" in the pin table at places where the type tlvled is required. PLUS pins are indicated by their name in double speech marks. Examples: "PLUS LED1", "2"
tlvconnectordetectionpin tlvconnectordetectionpin is the data type for connector detections of the W484-PLUS-Matrix. You must pass pins which are tagged as "Connector detection" in the pin table at places where the type tlvconnectordetectionpin is required. PLUS pins are indicated by their name in double speech marks. Examples: "PLUS CD1", "3"
tlvpoweru1pin tlvpoweru1pin is the data type for power u1 pins of the W484-PLUS-Matrix. You must pass pins which are tagged as "Power U1" in the pin table at places where the type tlvpoweru1pin is required. PLUS pins are indicated by their name in double speech marks. Examples: "PLUS Power U1 1", "4"
tlvpowerpin tlvpowerpin is the data type for power pins of the W484-PLUS-Matrix. You must pass pins which are tagged as "Power" in the pin table at places where the type tlvpowerpin is required. PLUS pins are indicated by their name in double speech marks. Examples: "PLUS Power1", "5"
tarray tarray is a list (one-dimensional field) of values. The values in a list are of the same data type in most cases. (List of strings, list of pins etc.) A list can be passed to a function either as a variable or as an enumeration. In the case of an enumeration, the complete list of values must be enclosed in square brackets and the individual values separated by commas.
tpinarray tpinarray is a list (one-dimensional field) of pins. A pin list can be passed to a function either as a variable or as an enumeration. In the case of an enumeration, the complete list must be enclosed in square brackets and the individual pins separated by commas. Example: ["Pin1", "Pin2", "Pin3"]
tstringarray tstringarray is a list (one-dimensional field) of strings. A string list can be passed to a function either as a variable or as an enumeration. In the case of an enumeration, the complete list must be enclosed in square brackets and the individual strings separated by commas. Example: [’Text1’, ’Text2’, ’Text3’]
tintegerarray tintegerarray is a list (one-dimensional field) of whole-number values. An integer list can be passed to a function either as a variable or as an enumeration. In the case of an enumeration, the complete list must be enclosed in square brackets and the individual values separated by commas. Example: [2, 4, 8, 16]
tcontactarray tcontactarray is a list (one-dimensional field) of contacts. A contact list can be passed to a function either as a variable or as an enumeration. In the case of an enumeration, the complete list must be enclosed in square brackets and the individual contacts separated by commas. Example: ["Contact1", "Contact2", "Contact3"]
tcreatearray tcreatearray is used for internal functions only. A variable name must be passed at this point. While it is executed, the function generates a list from the variable name and fills it with values.
tfunction tfunction is the data type for a function. A function name must be passed at this point. Depending on the use case, the passed function must have a certain list and a certain type.

Constants

Internal constants

Internal constants are identifiers to which fixed values are assigned. Examples of internal constants: TRUE, CLOSED, RLC_Rpar

Custom constants

Constants can also be defined within an ATS program. They are then available from this point on in all subsequent functions. The name of constants must begin with an upper case letter (A..Z). This can be followed by upper case (A..Z), lower case (a..z), digits (0..9) and the underscore character (_).
A block in which constants are defined must be identified by the keyword constants.

constants
begin
   MyConstantValue1 = 10;
   My100 = 100;
end;

Result constants

Result constants are only used in the templates of the programs for creating reports. These constants can be used to access the data of a test step and convert them to output texts for screens or reports. All result constants begin with the string "RES_".
The result constants that are available for the individual test steps can be found in the reference of the ATS functions for the particular test step.
Examples: RES_Pin1, RES_Result

Identifiers

Identifier is a generic term for variable, constant and function names.

Expressions

An expression is a construct that delivers a value. Arithmetical (2 + 3), logical (Success AND Valid) and relational expressions (Value <= 100) are available in ATS.

Operators

Operators are characters or words which control command sequences.
In ATS, a difference is made between arithmetical, logical and relational operators.

Arithmetical operators

Please consider that CEETIS does not meet the order of operations 'multiplication/division precedes addition/subtraction'. CEETIS processes arithmetical expressions from left to right. Please use parantheses to observe this rule. Notice: If an arithmetical addition can't be executed with the two specified operands, the values are concatenated and assigned to the result.
Operator Operation Operand type Result type Example:
+ Addition integer, real integer, real Var1 + 3
- Subtraction integer, real integer, real Value - 1
* Multiplication integer, real integer, real Length * 3
/ Floating-point division integer, real real Voltage / Current

Logical operators

These operators obey the standard rules of boolean logic. For example, an expression in the form ValueX AND ValueY only delivers the value TRUE when ValueX and ValueY have the value TRUE.
Please consider that CEETIS does not meet the order of operations 'NOT precedes AND' and 'AND precedes OR'. CEETIS processes logical expressions from left to right. Please use parantheses to observe this rule.
Operator Operation Operand type Result type Example
AND Logical AND (conjunction) boolean boolean Success AND Valid
OR Logical OR (disjunction) boolean boolean Less OR Equal
NOT Logical NOT (negation) boolean boolean NOT Valid

Relational operators

Relational operators are used to compare two operands.
Operator Operation Operand type Result type Example
== Equal to real, integer, boolean boolean Value == 100
<> Not equal real, integer, boolean boolean Result <> 0
< Less than real, integer, boolean boolean Count < 10
> Greater than real, integer, boolean boolean Number > 100
<= Less than or equal to real, integer, boolean boolean Counter <= 1000
>= Greater than or equal to real, integer, boolean boolean Value >= 20

Statements

Statements define the actions in a program. Simple statements (e.g. assignments and procedure calls) can be combined. Loops, conditional statements and other structured statements can be generated in this way.
Multiple statements in a block are separated from semicolons.

Simple statements

Assignments

An assignment is a type of statement that assigns a new value to a variable. If <Var> is a variable and <Expr> an expression, then in ATS

<Var> = <Expr>;

assigns the value of the expression <Expr> to the variable <Var>.

Value = 10.3;
Text = 'Hello world!';
Current = 10mA;

If – as in the last example – a value with a unit is assigned to a variable, the value is converted to its basic unit. In this example, after the assignment the variable "Current" contains the value 0.01 (and not 10).

Function calls

A function call consists of the name of a function and (if necessary) the parameters.
Functions that return a value can also be used in an assignment. If a function which returns a value is not called in an assignment, the return value is discarded.
Here are some examples of function calls:

Sum = add_values(1, 3);
UIWriteNormal('Hello world!');
do_something();

Structured statements

Structured statements are built up from other statements. They are used when other statements are to be executed sequentially, repeatedly or dependent on a condition.

Combined statement

A combined statement is made up of a sequence of other (simple or structured) statements that are executed in the order indicated. The sub-statements contained in a combined statement are enclosed between the keywords begin and end and separated by semicolons.

begin
   Exchange = Value1;
   Value1 = Value2;
   Value2 = Exchange;
end;

if statement

There are two kinds of if statement: if... and if... else....
The syntax for an if... statement is

if (<expression>)
begin
   <statements>
end;

The result of <expression> is a value of the boolean type. <Statements> is only executed when the expression gives the value TRUE.

if (Value2 <> 0)
begin
   Result = Value1 / Value2;
end;

The syntax for an if... else... statement is

if (<expression>)
begin
   <startements1>
end
else
begin
   <statements2>
end;

The result of <expression> is a value of the boolean type. If the expression gives the value TRUE, <statements1> is executed, otherwise <statements2>.

if (Value2 <> 0)
begin
   Result = Value1 / Value2;
end
else
begin
   Result = 0;
end;

switch statement

The switch statement is an alternative to the if statement that should be used with complex nestings because of its superior legibility.
The syntax of a switch statement is

switch (<SelectorExpression>)
begin
   case <Case>:
   begin
      <Statements1>
   end;
   case <Case2>:
   begin
      <Statements2>
   end;
   ...
   case <CaseN>:
   begin
      <StatementsN>
   end;
end;

Here, <SelectorExpression> is any random expression of the type integer, string, real or boolean.
Constants or fixed values of the type integer, string, real or boolean can be used for <Case1> to <CaseN>. Variables are not allowed. Each of the values <Case1> to <CaseN> must be unique within the list.
The corresponding statement list is processed depending on the value of <SelectorExpression>. If <SelectorExpression> has a value that does not occur in the list, the complete switch statement is skipped.
A switch statement can have a terminating default section.

switch (<SelectorExpression>)
begin
   case <Case1>:
   begin
      <Statements1>
   end;
   case <Case2>:
   begin
      <Statements2>
   end;
   ...
   case <CaseN>:
   begin
      <StatementsN>
   end;
   default:
   begin
      <StatementsOther>
   end;
end;

If a default section is present, <StatementsOther> is executed if the value of <SelectorExpression> is not any value in the list.

The switch statement

switch (Button)
begin
   case DIALOGRESULT_Button1:
   begin
      UIWriteNormal('Button 1');
   end;
   case DIALOGRESULT_Button2:
   begin
      UIWriteNormal('Button 2');
   end;
   case DIALOGRESULT_Button3:
   begin
      UIWriteNormal('Button 3');
   end;
   default:
   begin
      UIWriteNormal('Other button');
   end;
end;

is identical with the following nested if statement:

if (Button == DIALOGRESULT_Button1)
begin
   UIWriteNormal('Button 1');
end
else
begin
   if (Button == DIALOGRESULT_Button2)
   begin
      UIWriteNormal('Button 2');
   end
   else
   begin
      if (Button == DIALOGRESULT_Button3)
      begin
         UIWriteNormal('Button 3');
      end
      else
      begin
         UIWriteNormal('Other button');
      end;
   end;
end;

Loops

Loops allow the repeated execution of a sequence of statements. A condition or a variable determines when the execution is stopped. ATS supports three types of loop: do-while, while and for loops.

do-while loop

The syntax for a do-while loop is:

do
begin
   <statements>
end
while (<expression>);

The result of <expression> is a value of the boolean type. All statements inside the loop are executed in sequence. The specified expression is evaluated after each cycle. If <expression> delivers the value FALSE, the do-while loop is ended. Because <expression> is only evaluated at the end of the first iteration, the sequence of statements is run through at least once.

Value1 = 0;
Value2 = 1;
Fibonacci = Value1 + Value2;
Maximum = 1000;
UIWriteWarning(StrAdd('Fibonacci 1 - ', Maximum));
do
begin
   if (Value1 < Value2)
   begin
      Value1 = Fibonacci;
   end
   else
   begin
      Value2 = Fibonacci;
   end;
   UIWriteNormal(Fibonacci);
   Fibonacci = Value1 + Value2;
end
while (Fibonacci <= Maximum);

while loop

A while loop is similar to a do-while loop in many respects, except that the condition is evaluated before the first cycle of the sequence of statements. If the result of the condition is FALSE, the sequence is not executed.
The syntax for a while loop is:

while (<expression>)
begin
   <statements>
end;

The result of <expression> is a value of the boolean type. The while loop executes <statements> repeatedly and evaluates the specified expression before each new cycle. The sequence is repeated for as long as <expression> gives the value TRUE.

Value1 = 0;
Value2 = 1;
Fibonacci = Value1 + Value2;
Maximum = 1000;
UIWriteWarning(StrAdd('Fibonacci 1 - ', Maximum));
while(Fibonacci <= Maximum)
begin
   if (Value1 < Value2)
   begin
      Value1 = Fibonacci;
   end
   else
   begin
      Value2 = Fibonacci;
   end;
   UIWriteNormal(Fibonacci);
   Fibonacci = Value1 + Value2;
end;

for loop

Unlike the do-while and while loop, with a for loop the number of times which the loop should cycle is specified.
The syntax for a for loop is:

for <count> = <start value> to <end value> do
begin
   <statements>
end;

where <start value> and <end value> must be integers and <statements> must not change the value of <count>.

The 'for' loop assigns the specified start value to <count> and then executes <statements> repeatedly. The value of <count> is incremented with each cycle. As soon as the value of <count> is identical with the value of <end value>, <statements> is run one more time and the for loop is then ended. <Statements> is therefore run once for each value that lies within the range <start value> to <end value>. If <start value> and <end value> are identical, <statements> is run precisely once. If <start value> in a 'for' loop is greater than <end value>, <statements> is not run at all. After the end of the 'for' loop, the value of <count> is not defined.

for Count = 1 to 10 do
begin
   UIWriteWarning(StrAdd(Count, ': Hello world!'));
end;

Functions

Functions are in ATS subroutines. A distinction is made between internal and custom functions.

Internal functions

The internal functions in ATS are the functions that are permanently implemented in CEETIS (e.g. WireTest). They can be called with parameters and their return values are evaluated. A list and descriptions of all the internal functions will be found in the Reference of ATS Functions.

Custom functions

ATS also allows you to write and call your own functions. Custom functions are optional. The only function that must exist in all programs (except report generating) is the "main" function.
Functions can have one or more call parameters and return a function value after they end. Functions are defined with the keyword function. This is followed by the function name, the (optional) parameter list, the result type of the function and (optional) directives.
Syntax:

function <function name>(<optional parameter list>): <datatype>; <optional directives>
begin
   <statements>
end;

Example of a function declaration:

function add_values(Var1: integer; Var2: integer): integer; manualtest; rangetest;
begin
   Result = Var1 + Var2;
end;

Function names

The name of a function must begin with a lower case letter (a..z). This can be followed by more lower case letters (a..z), digits (0..9) and the underscore character (_).

Parameters

If you want to be able to pass parameters to a function, you must specify them by name and data type. Parameters are normally passed as a value ('by value'); the value of a variable that is passed to a function as a parameter is not changed when the function is executed (unless there is an explicit assignment outside the function).
However it is also possible to define the pass 'by reference' using the keyword var, e.g. as with the function "inc":

function inc(var Value: integer): void;
begin
   Value = Value + 1;
end;

Result type

The result type of a function defines the type of the value that is returned by the function. If you do not wish a function to return a value, you must specify void as the result type.

Return value

The return value of a function must correspond to the defined result type. A function returns the value that was last assigned to the variable Result within its statement list.

function add_3_values(Var1: integer; Var2: integer; Var3: integer): integer;
begin
   Result = Var1 + Var2;
   Result = Result + Var3;
end;

Directives

Directives are words that are treated specially at certain places in the source text. Possible directives for functions are manualtest, rangetest and tests. It is also possible to specify several directives for a function. No one directive may be duplicated however.

The directive manualtest

If the directive manualtest is specified for a function, that function can be called from the manual test.

function my_manualtest_comment(Comment: string): void; manualtest;
begin
   UIWriteNormal(Comment);
   ReportWriteNormal(Comment);
end;

The directive rangetest

If the directive rangetest is specified for a function, that function can be called from the range test.

function my_rangetest_comment(Comment: string): void; rangetest;
begin
   UIWriteNormal(Comment);
   ReportWriteNormal(Comment);
end;

The directive tests

The tests directive can be used to define the type of components which this function tests. As a result, an alignment is carried out with the network list when the program is compiled. The compiler does not output the warning "component may not be tested" for components that are tested with such a function.
After the keyword tests you must specify the type of components that you wish to test with this function.
Permitted values are:
wires, resistors, switches, capacitors, diodes, zdiodes, ctwists, rlccombinations, attenuators, customcomponents, variable_resistors, opticalfibers
In the case of functions with the tests directive, the first three parameters are also mandatory and must be given. These parameters are Name, Pin1 and Pin2. They can be followed by any other desired parameters.

function my_wiretest(Name: string; Pin1: tpin; Pin2: tpin; ErrorText: string): boolean; tests wires;
begin
   Result = WireTest(Name, Pin1, Pin2);
   if (NOT Result)
   begin
      UIWriteError(ErrorText);
      ReportWriteError(ErrorText);
   end;
end;

The directive adds_to_net_list

The directive adds_to_net_list tells the compiler that a function adds a component of a certain kind to the netlist. This prevents the compiler from displaying a warning if components are tested which are added to the netlist during run time.
After the keyword adds_to_net_list you must specify the type of components that you wish to add with this function.
Permitted values are:
wires, resistors, switches, capacitors, diodes, zdiodes, ctwists, rlccombinations, attenuators, opticalfibers
In the case of functions with the adds_to_net_list directive, the first three parameters are mandatory and must be given. These parameters are Name, Pin1 and Pin2. They can be followed by any other desired parameters.
The function NWAddWire has got such a directive. Because of his the following example raises only one compiler warning. If the example is executed there will be an error massage during the test as soon as the first WireTest is about to be executed. This happens because the wire is not yet known at this point.
function main(): void;
begin
   UIClearScreen();
   WireTest('New wire', "1", "2");
   NWAddWire('New wire', "1", "2", []);
   WireTest('New wire', "1", "2");
end;

The directive removes_from_net_list

The directive removes_from_net_list tells the compiler that a function removes a component of a certain kind from the netlist. This makes the compiler to display a warning if components are tested which were removed from the netlist during run time.
After the keyword removes_from_net_list you must specify the type of components that you wish to remove with this function.
Permitted values are:
wires, resistors, switches, capacitors, diodes, zdiodes, ctwists, rlccombinations, attenuators, opticalfibers
In the case of functions with the removes_from_net_list directive, the first three parameters are mandatory and must be given. These parameters are Name, Pin1 and Pin2. They can be followed by any other desired parameters.
The function NWRemoveWire has got such a directive. Because of his the following example raises a compiler warning. If the example is executed there will be an error massage during the test as soon as the second WireTest is about to be executed. This happens because the wire is no longer known at this point.
function main(): void;
begin
   UIClearScreen();
   NWAddWire('New wire', "1", "2", []);
   WireTest('New wire', "1", "2");
   NWRemoveWire('New wire', "1", "2");
   WireTest('New wire', "1", "2");
end;

The 'main' function

The 'main' function must be present in programs for project selection, programs for test initialisation, programs for test end and in test programs (Projects). (In report creation programs its task is performed by the templates.) The function has no parameters and its result type is always void.

function main(): void;
begin
   test_my_uut();
end;

A program always runs by the 'main' function being executed. Other functions are only executed if they are called within 'main' or by one of these functions.
In many cases the entire test sequence need only be written in the 'main' function, so no other custom (user-defined) functions are necessary.

Templates

General

Templates are used in report creation programs instead of the 'main' function.
For each test step that can report its results (e.g. WireTest, SwitchTest, ResistorTest), there is a maximum of one template in the programs for report creation. If there is no template for a particular test step, the template from the standard programs supplied with CEETIS is used.
There are also special templates for the header and footer of a report. Always run the appropriate template to output a test step on screen or in the report.
Templates are defined with the keyword template. This is followed by the name which must be the name of a test step.

template WireTest
begin
   ...
end;

The text that will be output on screen or in the report is now generated within the template. The functions UIWriteNormal, UIWriteWarning or UIWriteError can be used to display text on screen. The functions Write and WriteLn are available for writing to the report.
Within a template, the data of the test step can be accessed via result constants.
Here is an example of the output of WireTest on screen:

template WireTest
begin
   //get name of Pin1
   Pin1 = PinGetData(RES_Pin1, PIN_AnyName);
   Pin1 = FormatAlignLeft(Pin1, 15, ' ');
   //get name of Pin2
   Pin2 = PinGetData(RES_Pin1, PIN_AnyName);
   Pin2 = FormatAlignLeft(Pin2, 15, ' ');
   //assemble pins
   Pins = StrAdd(Pin1, Pin2);
   if (RES_Result == TESTSTEP_Passed)
   begin
      //define result text
      ResultText = FormatAlignLeft('Passed', 15, ' ');
      //assemble the output line
      Line = StrAdd(ResultText, Pins);
      //output text
      UIWriteNormal(Line);
   end
   else
   begin
      //define result text
      ResultText = FormatAlignLeft('Failed', 15, ' ');
      //assemble the output line
      Line = StrAdd(ResultText, Pins);
      //output text
      UIWriteError(Line);
   end;
end;

The header template

The 'header' template can be used to define which text (or images) is always output at the start of a report. In the standard reports supplied with CEETIS, the report headers always display information about the unit under test and the test result.

The footer template

The 'footer' template can be used to define which text (or images) is always output at the end of a report. In the standard reports supplied with CEETIS, the footer template is only used for the HTML version of the report. It ensures that the end tags needed for an HTML file are inserted into the report file at the end.
